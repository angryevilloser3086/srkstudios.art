Capabilities

Engineered beyond the happy path

Most plugins work in a demo. This one is designed for the messy reality of production devices, OEM quirks, and third-party SDKs.

Runtime Icon Switching

Change the launcher icon on the fly on both Android and iOS. On Android, optional app relaunch support keeps the transition seamless for the user.

Scheduled Changes

Schedule an icon to activate at a future time and automatically reset afterwards — ideal for seasonal campaigns, festivals, and limited-time events.

State Recovery

Icons survive device reboots and app updates. The plugin automatically restores the correct icon state on boot — no stale or broken launcher entries.

Protected Components

A Protected Components API keeps third-party SDK components (push notifications, deep links, analytics) safe while activity aliases are switched.

OEM Blacklist Support

Some manufacturers handle activity-alias switching poorly. Built-in OEM blacklisting lets you gracefully skip problematic devices instead of crashing.

iOS Badge Numbers

First-class badge management on iOS — set and read the app badge number right alongside icon changes, from a single unified API surface.

Getting Started

Up and running in minutes

Three steps from install to your first dynamic icon change.

1

Install the package

Add the dependency to your pubspec.yaml and fetch packages.

pubspec.yaml 
dependencies:
  dynamic_app_icon_changer: ^0.0.3
2

Configure your platforms

Android — declare an activity-alias per icon in AndroidManifest.xml, add icon drawables to your mipmap directories. iOS — drop icon PNGs into the Runner directory and register them under CFBundleIcons in Info.plist. Full step-by-step guides are in the package README.

3

Switch icons from Dart

One import, one call. The same API works on both platforms.

main.dart 
import 'package:dynamic_app_icon_changer/dynamic_app_icon_changer.dart';

// Anywhere in your app:
await DynamicAppIconChanger.setAlternateIconName('IconBlue');

API Overview

A small, focused API

Everything you need for dynamic icons — nothing you don't.

setAlternateIconName(String? name)

Switch the launcher icon. Pass an icon name to activate it, or null to restore the default icon.

alternateIconName

Returns the currently active alternate icon name, or null when the default icon is in use.

scheduleAlternateIcon(...)

Schedule an icon change for a future time with automatic reset — perfect for time-boxed seasonal icons.

registerProtectedComponents(...)

Register third-party SDK components (push, deep-link handlers) so alias switching never disables them.

setBadgeNumber(int) / badgeNumber

Set and read the app badge count on iOS from the same plugin — no extra dependency needed.

Frequently asked questions

Are SRK Studios packages free to use commercially?

Does changing the app icon require an app restart?

No restart is required to trigger the change. On iOS the system swaps the icon immediately (with a system alert). On Android, activity-alias switching may briefly relaunch the app — the plugin includes app relaunch support to make this transition smooth.

Will icon switching break my push notifications or deep links?

This is exactly what the Protected Components API is for. Register your third-party SDK components with registerProtectedComponents() and they remain enabled while launcher aliases are switched.

What happens after a device reboot or app update?

The plugin automatically recovers its state on boot and after app updates, restoring the icon the user last selected. Scheduled icons also resume or reset correctly.

Which devices are known to be problematic?

A small number of OEM launchers handle activity aliases poorly. The plugin ships with OEM blacklist support so you can skip icon switching gracefully on those devices instead of degrading the user experience.
